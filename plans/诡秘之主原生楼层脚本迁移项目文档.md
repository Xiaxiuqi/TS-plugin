# 诡秘之主原生楼层脚本迁移项目文档

> 最后更新：2026-09-17  
> 状态：进行中  
> 工作目录：`public/guimizhizhu_ui/`

## 1. 目标

将 `数据库前端/regex-正文-诡秘之主catiger95-脚本分块/` 中的正则 `replaceString` 脚本，迁移为可由酒馆助手加载的模块化脚本项目。

迁移后的叙事时间线只能使用 SillyTavern 的真实聊天楼层：每次剧情行动必须产生一条真实 `user` 楼层和一条真实 `assistant` 楼层。前端输入框与酒馆原生输入框必须经过同一回合编排器，且不会重复发送。

## 2. 强制边界

- 不再劫持或替换酒馆原生聊天楼层。
- 不再使用 `chatHistoryCache`、`historyViewIndex`、私有快照、私有分支或时间线目录保存叙事历史。
- 不再写入每回合正文到 0 号消息；回合状态写入对应真实 assistant 楼层的 `data`。
- 删除默认长线记忆、核心记忆总结、精准记忆召回（RAG/API 1）及其设置、持久化、索引、API 调用和 UI。
- 保留与记忆无关的世界书、角色、战斗、抽卡、变量 AI、前端工具和“本周目经历”业务功能。
- 旧私有快照与用户既有世界书数据不主动删除；新版本只停止读取和写入它们。

## 5. 回合模型

```text
前端 quick-send / 行动选项 / 酒馆原生输入
  -> input-adapter
  -> turn-orchestrator.submitNativeTurn(rawText, source)
  -> 创建真实 user 楼层
  -> generation-bridge 构建保留上下文与生成请求
  -> TavernHelper.generate
  -> 校验、解析 MVU、结算
  -> 创建真实 assistant 楼层并写入 data
  -> 刷新受影响楼层、清理忙碌状态
```

`generate()` 的 Promise 与生成结束事件必须由同一个 transaction 的幂等锁保护，确保只提交一次 assistant 楼层。失败、取消或质量检查拒绝时，只能删除当前事务创建且尚未配对的 user 楼层。

## 6. 无记忆提示词策略

`prompts/native-history-policy.js` 将生成一个固定 system 注入，不执行检索、不写存储、不携带旧快照：

```text
本轮不提供自定义长期记忆、核心记忆或 RAG 召回。请仅依据系统规则、世界书、当前原生聊天记录与本次用户输入推进剧情。未出现在当前上下文中的既往信息不得擅自补造；信息不足时应以当前可见事实为准。
```

该提示用于明确移除记忆功能后的模型行为边界，不能成为变相的记忆载体。

## 10. 验收清单

- 前端输入发送一次：恰好新增一条真实 user 与一条真实 assistant 楼层。
- 酒馆原生输入发送一次：同样恰好新增一对楼层，无默认发送导致的重复 user 楼层。
- 酒馆原生编辑、删除、重生成与滚动能直接作用于真实楼层。
- 编辑器只更新目标 assistant 楼层的 `message` 和 `data`。
- 生产代码不再引用 `chatHistoryCache`、`historyViewIndex`、`isHistoryViewMode`、`renderHistoryControls`、`_retrieveRelevantMemories`、`_assembleCoreMemory`、`RAG_AI_KEYS`、`writeSummaryToLorebook`。
- 正文生成请求不包含近期经历切片、核心记忆或 RAG 召回；RAG API 不会被调用。
