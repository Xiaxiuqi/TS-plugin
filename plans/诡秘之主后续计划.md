# 诡秘之主后续计划

> 制定日期：2026-11-19
> 现状依据：[总览](./诡秘之主原生楼层迁移总览.md)、[功能对账](./诡秘之主原版功能对账.md)

## 现状判断

- 功能对账里除 QuickRomanceWindow 外都标为“已迁入”，但这只代表隔离预览和具名测试通过。**真实 SillyTavern 里一次都没验收过**（总览第 6 节）。
- 最近一次 git 提交是 5 周前。`public/guimizhizhu_ui`、`tests`、`plans` 下有约 380 个未跟踪文件和约 120 个已修改文件。不提交的话，任何一次误操作都可能丢掉几周的工作。
- 已知失败的测试有 5 个（见总览第 5 节），其中 `cashflow` 和 `battle-possession` 可能是代码真坏了。
- 旧的单敌个人战斗 `core/personal-battle-state` 仍被 31 个 core 和模块文件引用。新对局已经走统一战斗。

所以接下来的重点是把已经做出来的东西稳住、在真实宿主里验收，**不再继续扩大迁移范围**。

## 阶段与完成标准

每个阶段完成才进入下一阶段。每个阶段做完都在历史日志里追加不超过 5 行记录。

3. 分批中文 commit：`shared`+`core`、`modules`、`tests`、`tools`+`plans`。

完成标准：总览第 5 节的“已知失败”清空，`git status` 里 `guimizhizhu_ui` 相关路径全部干净。

### P1 原生楼层真实宿主验收

这是“恢复原生楼层”目标唯一没完成的部分。需要用户授权使用一个**专门的测试聊天**，不碰正式聊天。

1. 加载与热重载：`window.cryptLord?.loader?.status === 'ready'`，控制台无报错。
2. 一回合：原生输入发送、行动选项填入后发送，各恰好新增一对 user/assistant 楼层，变量写在 assistant 楼层的 `data`。
3. 楼层操作：编辑、删除、重生成、切 swipe、切换聊天后，状态栏和选项跟着当前楼层走，没有旧楼层残留。
4. 失败路径：生成中停止、质量检查拒绝，只删除本回合的 user 楼层。
5. 抽查写入功能：每个功能域挑 1 个窗口（变量编辑、物品栏、产业、战斗一局、一个途径窗口），保存后刷新页面，读回结果一致。

用 `tests/guimizhizhu_ui/real-host-audit.console.js` 记录。发现的问题按功能域登记到对账文档的“备注”列，状态改为“部分”。

完成标准：1 到 4 全部通过，5 的问题都已登记。

链路问题（第 1、2、4、6 条已在 P1 期间修复，第 3、5 条在 P1 结束后统一修）：

1. 【已修】副模型 `generateRaw` 会再触发一次 `GENERATION_STARTED/AFTER_COMMANDS`，参数与正常回合相同。现在 `hostApi.generateRaw` 计数“副请求进行中”，`afterNativeHost.bindEvent` 在副请求期间丢弃这两个事件，所有模块统一生效；线索模块的单独补丁已撤回。
2. 【已修】来源校验过宽：原生楼层和 state-store 的来源比较改为“楼层数 + 最后两层的楼层号、正文、swipe、变量”；剧情归档的 `floorSignature` 忽略 `is_hidden/extra`。读取次数未减少，留到第 3 条一起处理。
3. 取消逻辑分散：原生楼层、生成桥接、state-store、线索、动态状态、剧场各自维护 epoch/guard/beforeWrite。应由原生楼层持有一个回合凭据，其他模块只校验凭据。
4. 【已修】DOM 观察器空转：已删除，结算只靠 `MESSAGE_RECEIVED`，安装时补结算最后一层。
5. 【已修】失败提示不准：原生楼层的 AbortError 区分“正文来源被改 / 聊天或脚本切换 / 模块取消”三种提示，并写诊断日志 `native-assistant-aborted`。
6. 【已修】模板世界书重复读取：首次请求不再重读，只在重试前读取并比较版本，且跳过 JSON 解析。

统一修正结果：

- 【已修】聊天 ID：宿主 `SillyTavern` 全局没有 `getCurrentChatId`，只有 `getContext().getCurrentChatId`。18 个模块的身份检查原来一直拿到 undefined，现已加回退。
- 【已修】快捷指令重复：原版解析不报错。现在保留第一次出现的那条，不再拒绝加载。
- 【已修】战斗提示条目：只有“【判定】战斗”是必需的，其余陪伴条目在本卡世界书缺失时跳过。
- 【已修】诊断按钮：按钮 API 只存在于脚本自身的 iframe，现按脚本 id 找到该 iframe 注册，已在宿主中注册成功。
- 【已修】战斗提示 / 剧情归档的“回合前状态已变化”：上一层的比较改为忽略 `is_hidden/extra`。
- 不改：user 楼层的“以下是用户的本轮输入”包装来自外部数据库/记忆召回插件及其美化正则，不是本项目写入。
- 不改：切换预设关闭测试脚本。脚本已迁为角色脚本，后续如复现再查。
- 未做：第 3 条“统一回合凭据”属于结构改造，移入 P3（与 C3 生成守卫合并）。
- 回归：可见窗口重新生成一回合，时间 09:10→09:20，地标、选项（6 个）正常，无警告。
